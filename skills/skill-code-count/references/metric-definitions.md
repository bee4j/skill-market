# 统计口径定义

## cloc 三分类

| 指标 | 含义 | 是否计入“工程量” |
| :--- | :--- | :--- |
| **code** | 实际代码行，不含注释和空白 | **是**，首选指标 |
| **comment** | 注释行（单行注释、块注释中的非空行） | 否，但注释率是质量参考 |
| **blank** | 空白行 | 否 |

**注释率** = comment / (code + comment)。一般项目 10%–25% 为常见区间，过低可能意味着可维护性风险，过高需结合文档规范判断。

## 快照口径 vs 历史口径

| 口径 | 命令 | 含义 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **快照** | `cloc --vcs=git` | 当前 Git 跟踪文件的静态行数 | 量化项目**当前规模** |
| **历史变更** | `git log --numstat` | 提交历史中的增删行累计 | 量化**开发投入**、按人贡献 |

**关键区别**：
- 快照口径下，一个文件被重写 10 次，只计最终行数。
- 历史口径下，同样 10 次重写会累计 10 次的增删行，数值通常远大于快照。
- **两者不可相加、不可直接对比**。输出时必须标注口径。

## 净增行数的局限

`净增行数 = 新增行 - 删除行`，能反映代码库的净增长，但：
- 重构、格式化、依赖升级会产生大量增删，不代表实际工作量。
- 生成代码（如 protobuf、ORM 迁移）会显著抬高新增行。
- 建议同时给出**提交数**作为辅助参考，避免单一指标误判。
